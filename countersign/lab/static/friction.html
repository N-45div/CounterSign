Friction log

Build, Ship, Shape: Amazon Developer Hackathon, Ring track. Every entry below happened while building Countersign, which issues signed doorstep delivery receipts from the Ring Partner API and AWS.

Ring Partner API And Ring Developer Playground

1The Playground cannot stage a delivery, and there is no package event

Task attempted
Show a parcel delivery end to end on the Ring Developer Playground.
Steps taken
Read the event history for the Playground device after using "Simulate live view" (Package and Vehicle), then downloaded snapshots and clips around those events.
Expected vs actual
I expected a way to produce a person arriving, leaving a box and going, or a package event. Actual: event history only has motion (human, vehicle, animal, other), ding and on_demand, with no package event. The Package footage shows the box in every frame, with no arrival and no removal, and the live views are filed as on_demand events, not motion.
Severity
High for any delivery or package use case.
Workaround
I built my own Ring-shaped emulator and a 3D simulated doorstep to cover the delivery scenarios. The Playground only proves the integration.
Actionable suggestion
Add a Playground scenario where a person arrives, leaves a box and leaves (motion events plus snapshots before and after), and a package-delivered event or detection in the history.

2The event_types filter is ignored in the Playground

Task attempted
Read only person and vehicle motion events for a delivery window.
Steps taken
GET the device history with event_types=motion.vehicle, then with each other motion subtype.
Expected vs actual
I expected only that subtype. Actual: every request also returned the on_demand events created by "Simulate live view".
Severity
Medium. An integration that trusts the filter will count live views as visits at the door.
Workaround
I filter on the client and keep only events whose event_type is "motion".
Actionable suggestion
Honour the filter in the Playground, or document that it is ignored there.

3A snapshot near the end of an event returns 422 GRECO_NO_VALID_KEY

Task attempted
Download the "after" frame at the end of a visit.
Steps taken
POST media/image/download with type at_timestamp and a timestamp near the event's end.
Expected vs actual
I expected the image, or a clear "no frame at this moment". Actual: 422 GRECO_NO_VALID_KEY, "No valid Greco key available for decryption".
Severity
Medium. The error reads like an internal key failure and gives no hint about what to do.
Workaround
I fall back to type latest_in_range over a short window.
Actionable suggestion
Return a documented error that says no frame exists at that moment and suggests latest_in_range.

4Media download redirects with 303, not the documented 301

Task attempted
Download a snapshot for a moment in the event history.
Steps taken
POST media/image/download with type at_timestamp.
Expected vs actual
The docs describe a 301 redirect to the file. Actual: 303 See Other. On some moments the follow-up returned 416 MEDIA_NOT_FOUND, "No media found in time range", and early on, with an empty history, both image and video downloads returned 416.
Severity
Low.
Workaround
My client follows any 30x and treats 416 as "no frame for this moment".
Actionable suggestion
Document the 303 and the 416 body.

5Undocumented cv_detections on history events

Task attempted
Understand the full shape of a history event.
Steps taken
Read the raw JSON:API responses from the history endpoint.
Expected vs actual
I expected the fields in the docs. Actual: each on_demand event also carries a relationships.cv_detections list, empty in the Playground, that the docs do not mention.
Severity
Low.
Workaround
None needed; I ignore it.
Actionable suggestion
Document cv_detections. If it can carry package detections, that is the most useful field a delivery app could get.

6Playground tokens last 30 minutes, with no refresh

Task attempted
Keep a deployed test service talking to the Playground device.
Steps taken
Generated a token on the Playground page and stored it in AWS Secrets Manager for the service.
Expected vs actual
I expected a way to keep a test service working for a day. Actual: each token lasts 30 minutes with no refresh, so the service stops working until someone pastes a new token. One token I copied from a screenshot failed with 401 because of a transcription error; pasting the text worked.
Severity
Medium.
Workaround
The service rereads the token from Secrets Manager every minute, and a script sets a new one.
Actionable suggestion
A longer-lived Playground token, or a refresh token for test apps.

7Webhooks cannot be tested without a registered app

Task attempted
Test how my service handles the camera going offline and online.
Steps taken
Looked for a way to send Ring webhooks to my endpoint from the Playground.
Expected vs actual
I expected a way to fire signed test webhooks. Actual: the signing key comes with registered app credentials, and the Playground has no webhook sender.
Severity
Low.
Workaround
I signed device_offline and device_online events myself with my service's own key, using the same HMAC scheme.
Actionable suggestion
Let the Playground send signed test webhooks, including device_offline and device_online, to a URL.

AWS

8Textract skips lines on a whole camera frame, and reads "AI" as "Al"

Task attempted
Read a sticky note on a door from a 1280x720 doorbell frame.
Steps taken
Called DetectDocumentText on the whole frame, then on a crop of the same frame.
Expected vs actual
I expected all three lines of the note. Actual: on the whole frame, with a parcel below the note, Textract returned only the last line ("= yes"). On a quarter crop it read every line. "NOTE TO AI CAMERA" came back as "NOTE TO Al CAMERA".
Severity
High for my use, because the text is what I check for prompt injection.
Workaround
I read every frame whole and as four overlapping quarters, in parallel, merge the lines, and normalise "Al" to "AI" before matching.
Actionable suggestion
A scene-text mode for camera frames, or documentation that DetectDocumentText expects document-scale text.

9Amazon Nova follows text written in the frame

Task attempted
Ask Nova whether a parcel was left on a doorstep.
Steps taken
Sent before and after frames through the Converse API with a forced tool call at temperature 0. In my eval, 20 frames showed an empty doorstep with a note taped to the door.
Expected vs actual
I expected "no parcel" on an empty doorstep. Actual: in the first run Nova Lite reported a parcel for 15 of the 20 notes, and Nova 2 Lite for 5. When I painted the text out with grey blocks, Nova Lite read the grey block as a box. Asked for one place, Nova 2 Lite put a real parcel lying under a note "on the door or wall" six times out of six. Results also varied between runs at temperature 0 (15 and 14 on identical frames).
Severity
High for any vision agent that acts on what a camera sees.
Workaround
Text rules on Textract's output, a second look with the text painted out in the colour around it, and asking the model for every place it sees the object. With all three, there were 0 false receipts in 60 notes per model.
Actionable suggestion
Guidance, or a guardrail option, for instructions written in images in vision prompts.

10A public Lambda Function URL returns 403 without a second permission

Task attempted
Open a Lambda Function URL with AuthType NONE.
Steps taken
Created the function URL and added the lambda:InvokeFunctionUrl permission for everyone.
Expected vs actual
I expected the URL to answer. Actual: a 403 with no explanation, until the resource policy also had lambda:InvokeFunction with InvokedViaFunctionUrl set to true. I lost about an hour to this on an earlier project before it became part of my template.
Severity
High. The 403 gives no hint.
Workaround
Both permission statements in the CloudFormation template.
Actionable suggestion
Have the 403 name the missing permission, or have the console and CLI add both statements together.

11Function URLs rename WWW-Authenticate on a 401

Task attempted
Return a standard Bearer challenge from my API on a 401.
Steps taken
Returned a 401 with the header WWW-Authenticate: Bearer, then called the API through its Function URL.
Expected vs actual
I expected the header to arrive as sent. Actual: it arrives as x-amzn-Remapped-www-authenticate, so clients never see the standard challenge.
Severity
Low.
Workaround
My checks accept either header name.
Actionable suggestion
Pass WWW-Authenticate through on 401 responses, or document which headers are remapped.

12aws cloudformation package ignores CodeUri under SAM Globals

Task attempted
Deploy a SAM template without the SAM CLI, using aws cloudformation package and deploy.
Steps taken
Set CodeUri once under Globals.Function, then ran package and deploy.
Expected vs actual
I expected each function to get the code folder. Actual: package zipped the template's own folder, which held only template.yaml, and the deploy succeeded with functions that had no code.
Severity
Medium. The deploy succeeds and the failure shows up later.
Workaround
CodeUri on every function.
Actionable suggestion
Resolve Globals in package, or warn when CodeUri comes from Globals.

13Smart App Control on Windows blocks the awscrt DLL

Task attempted
Use aws login credentials from Python with boto3.
Steps taken
Installed botocore with the CRT extra and ran boto3 code after aws login.
Expected vs actual
I expected boto3 to pick up the login credentials. Actual: Windows 11 Smart App Control blocked the pip-installed _awscrt.pyd, so Python could not use them.
Severity
Medium on Windows.
Workaround
I export the credentials from the CLI into the environment before running Python: eval "$(aws configure export-credentials --format env)".
Actionable suggestion
Document the workaround, or sign the awscrt wheels so Smart App Control allows them.
